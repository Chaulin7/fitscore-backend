# assets/

Static marketing assets served by dedicated Express routes (not the `public/`
static middleware).

## `CVsprings-EU-AI-Act-checklist.pdf`

The one-page EU AI Act checklist for recruitment tooling (`DOC. CVSPRINGS-CHK-01`).

- Served at `GET /eu-ai-act-checklist.pdf` (inline, cached 1 day), linked from
  the landing page's demo section (`src/index.js`).
- Attached to the demo-request confirmation email (`src/routes/demo.js`), which
  gains a sentence noting the attachment. If the file is absent the route 404s,
  the landing link breaks, and a warning is logged at boot.

### Provenance — read before regenerating

This PDF is a **pre-built binary**. Its `Producer` metadata reads
`ReportLab PDF Library`, so it was generated by a Python script that **is not in
this repo** and was not found on the machine it was committed from. The binary
was committed on its own in `6123d49`.

### OPEN ITEM — the brandmark on this PDF is not durable

The CVsprings brandmark on page 1 was **not** produced by the generator. It was
stamped onto the finished binary after the fact, by a one-off pdf-lib script
(`scripts/stamp-checklist.js`, commit `e5d4545`), because the ReportLab source
was unavailable.

**Consequence: regenerating this PDF from that ReportLab source will silently
drop the mark.** Nothing detects it — no test covers a binary asset's contents,
and the file will still serve, still render, and still look plausible.

**Durable fix:** add the mark inside the ReportLab script and regenerate, then
delete `scripts/stamp-checklist.js` and this section. Until then, anyone who
regenerates must re-run the stamp; the script header documents how, including
how to rasterise the mark from `public/brandmark.svg` (pdf-lib embeds PNG/JPEG
only — it does not accept SVG).

The pre-stamp original is recoverable from `6123d49` if a clean base is needed.
